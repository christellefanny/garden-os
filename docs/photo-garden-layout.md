# Photo-derived garden layouts

Plan & Design → Upload a garden photo → choose Mixed garden, Container garden or Beds & borders. An account can request automatic detection; guests can mark areas manually. Both paths open the same review screen, with a photo overlay, editable names/types/geometry, optional measurements and notes, and explicit review confirmation. Create editable layout appends a separate unlinked design to the existing custom-layout collection. The existing editor supplies decorative plants, rotation, deletion, surfaces and optional creation of real growing spaces. Existing designs and garden/plant records are preserved.

This first release maps existing structures. It does not invent a new garden design, identify crops or infer sunlight, physical measurements or hidden beds. Photo perspective remains approximate, with the photo aspect ratio preserved in the resulting editor. Very small containers become minimum-size schematic markers. A compact photo reference is optional; originals are not added to the gallery. JPEG/PNG/WebP under 20 MiB are decoded, oriented and re-encoded locally (metadata stripped); analysis images max 1.3M characters, reference max 100k. HEIC requires export as JPEG.

## Server

`POST /api/photo-layout` validates a Supabase account token using the existing server auth helper. Only inline raster image data is accepted; arbitrary external URLs are rejected. Account-scoped scan reservations use the existing `garden_os_state` table and `garden_os_save_state` CAS RPC, five scans per UTC day with a 30-second cooldown; simultaneous requests cannot reuse a version. These application-level limits are not a replacement for provider billing limits (owners can modify their own state records). A dedicated service-owned quota table would harden limits against malicious account owners if public usage grows.

AI SDK 7 uses structured `generateText` output through Vercel AI Gateway. The live catalog was checked for `openai/gpt-6-luna` (vision and structured output); `GARDEN_PHOTO_MODEL` can override it. Authentication uses deployment OIDC automatically, or server-only `AI_GATEWAY_API_KEY` for local/non-Vercel deployments. No credentials were created, fetched or exposed. No production environment was changed. The Vercel team needs Gateway access/credits; failed scans leave the manual mapping path usable. No provider output is executed or used as record IDs. Coordinates, counts, kinds and names are validated before return and again before saving. Provider failure details, tokens, photos and prompts are not logged.

## Verification

Pure tests cover schema/geometry/input limits, identity isolation and scan quota. The route test uses an injected provider/auth/database fixture to verify auth, validation, quota reservation, container intent and safe error handling. Browser checks use isolated account/guest storage and mocked model responses, including corrections, old-layout preservation, photo reference, failure/manual fallback, mobile persistence and accessibility. Actual hosted model inference must be checked with a signed-in account and a chosen garden photo; fixture checks do not establish real-world detection accuracy.

Custom layouts (including an optional thumbnail) use the existing account synchronization and guest transfer. Before appending, the current storage copy is re-read and checked, and the total serialized collection is capped below the existing 1.5 MB state limit. Failed saves keep the draft open. Large collections can omit the reference thumbnail. A local save is not itself a cloud acknowledgement; Settings exposes synchronization status as before.
