# Garden photo albums and private cloud backup

Each garden detail view offers Pictures in the former Refresh position. Refresh garden remains under More. Albums use the garden's stable ID, so existing and future gardens work without templates or fake spaces. Upload multiple original raster images, assign a date and description, organize folders, filter by year and open full-size views. The journal's Photos view includes all of the account's albums and its previous unlinked pictures.

Signed-in accounts use a private Supabase Storage bucket, `garden-atelier-private-photos`, provisioned on the first authorized upload. Existing `garden_os_state` records hold per-upload and per-folder metadata with compare-and-swap versions. No SQL migration or new credentials are needed on production, which already has SUPABASE_SERVICE_ROLE_KEY. The key stays server-only. The preview environment currently does not have this secret: cloud operations there show a setup message rather than pretend backup succeeded. To test cloud storage on previews, add a sensitive branch-specific preview key through Vercel's dashboard; never put it into chat or the repository.

The authenticated API checks account ownership, optional garden ownership, file count, MIME type, sizes, metadata, path prefixes and expected versions. Browser uploads go directly to Supabase using path-scoped signed upload tokens. Reads use expiring signed URLs. No public photo bucket or anonymous list/read policy is created. Limits: 50 images per upload, 20 MiB per file, JPEG/PNG/WebP/GIF/AVIF. Original files are kept; images are not replaced by illustrations or downscaled.

IndexedDB retains a device copy. New uploads are committed locally first; a failed cloud upload leaves that copy and exposes Back up existing pictures. Existing local entries and folders are not silently discarded. Metadata edits require a successful versioned cloud save before changing the cache. Tombstones stop other device caches from resurrecting deleted entries, and removed object paths are removed after metadata commits. An interrupted upload may leave an unreferenced object for later maintenance; it remains private.

Guests remain local. On the existing Save to account flow, guest picture and folder records are copied to stable account IDs; guest originals stay intact. Copied pictures expose the backup action after sign-in. The ordinary guest-to-account transfer still uses existing cloud state and garden records.

Validation uses isolated Supabase/auth/storage fixtures and separate Chromium sessions. No real user photos, credentials or account data are part of tests. A production-account upload and second physical device check are still required after deployment; local fixture success must not be described as a completed live Supabase upload.

The garden creation/edit form now fills USDA hardiness zones from a U.S. ZIP (including ZIP+4) or city/state. The lightweight `/api/garden-zone` lookup reuses the existing verified USDA 2023 ZIP table and safe host allowlist, avoiding the full planting-calendar climate download. City matches require a confident U.S. match and matching state. Input is debounced, stale requests are cancelled, manual overrides win over pending results, saved zones are retained when editing, and lookup failure leaves manual entry available. Nothing is published without the owner's final approval.
