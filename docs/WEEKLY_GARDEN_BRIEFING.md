# Weekly garden briefing

Growing Calendar now includes “Weekly garden priorities,” with the user's example structure: three highest priorities, buy/prepare, can wait, and saved calendar steps. The report uses the selected user's cloud-saved garden, connected growing spaces/plants, Plant Vault statuses and varieties, indoor/outdoor calendar modes, exclusions, task completion, recent journal entries and measured harvest records. Existing saved layouts remain connected through their growing spaces; the briefing never guesses a plant's bed from an illustration.

Weather is resolved from City, State using Open-Meteo/GeoNames, or explicit coordinates. National Weather Service point forecasts and active alerts are fetched for U.S. locations. Issuance and retrieval times appear in the report. Forecasts older than 18 hours, ambiguous towns, missing locations and network failures produce an explicit limitation, without invented temperatures or weather deadlines. Forecast-driven actions apply only to the remaining current week. Illinois-specific garlic timing is labeled as regional guidance; other locations are directed to local Extension.

Recommendations use reviewed, species-specific rules linked to primary Illinois Extension pages. Relevant sources are checked for availability (daily cache); forecasts use a 10-minute cache. The engine does not generate arbitrary AI prose, scrape the entire internet, diagnose pests, interpret free-text planning notes automatically, infer soil moisture, or certify harvest maturity. Unsupported crops still retain their calendar reminders; detailed advice currently covers common vegetables, indoor/hydroponic crops, tender annuals, garlic, seed saving, recorded pests and season review. Notes are displayed transparently instead of treated as confirmed facts.

Weekly settings are stored inside the existing version-checked, owner-specific calendar state: opt-in, delivery weekday (Monday default), garden, optional coordinates and planning notes. No database migration or destructive record changes. Reading a report waits for pending Vault/calendar synchronization; the report API is read-only and requires authentication. Garden access is scoped to the owner and spaces are queried only through an owned garden ID. No account tokens, plant records or journal notes are sent to weather or Extension services.

The existing daily Vercel cron also evaluates weekly preferences directly from cloud state, even with the app closed. It sends one combined weekly/daily push per subscribed device and claims `last_sent_day` atomically to avoid duplicates. Failed pushes release the claim; expired subscriptions are removed as before. Weekly failures are counted and do not suppress daily reminders. Clicking a weekly notification opens `/?view=calendar&brief=weekly` and loads a fresh briefing. Settings alone do not grant browser notification permission: the user must enable phone notifications under Add reminder. Timing remains approximately 8–10 a.m. Central on the existing free-plan daily job. U.S. weather and Central-time delivery are current limits; large-scale multi-user dispatch beyond the existing 500-device batch needs a queue/pagination design.

Validation uses isolated fixtures, never the owner's garden or phone subscription. Unit tests cover dates, priorities, exclusions, indoor crops, finished crops, planted garlic, completed reminders, harvest unit separation, stale/missing weather, location ambiguity, safe source URLs, ownership, combined delivery, concurrent claims and push failure recovery. Browser checks trace UI→API→owner-scoped fixture database→forecast/source fixtures→report rendering, preference and completion persistence, notification deep link, 320/390/768/1536 layouts and desktop/mobile WCAG A/AA. Screenshots in docs/previews/weekly-brief-*.png use QA records and synthetic weather, not a real forecast.
