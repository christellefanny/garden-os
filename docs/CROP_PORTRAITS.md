# Vegetable portrait completion

New project asset: `public/conservatory/crop-portraits-v2.webp` (1254 × 1254), generated with the built-in image generation tool and encoded as WebP. The sixteen cells are representative botanical crop/type illustrations, not photographs or cultivar identification. They cover habanero, Scotch bonnet, serrano and red bell pepper; plum/Roma, cherry, beefsteak and dark tomatoes; romaine, butterhead, red leaf and oakleaf lettuce; red, yellow and white bulb onions and bunching onions.

The common portrait resolver now supplies these images in the Plant Vault, growing-space cards and any other shared plant portrait. Matching uses both crop name and variety, recognizes singular/plural crop names, and keeps saved photos first. Specific recognized forms get the corresponding tile. Less-specific crop records get an explicitly labeled representative illustration rather than a claim to depict an exact cultivar. Unknown species remain unmatched; no unrelated plant is inserted. This changes display only, without modifying saved garden records or the database.

Generation prompt: one exact 4-by-4, text-free botanical watercolor/pencil sprite sheet on ivory paper; equal isolated cells, generous margins, realistic vegetable morphology, no cartoons or cell overlap. Row 1: orange lantern-shaped habanero, red flattened Scotch bonnet, slender green serrano, compact red bell. Row 2: red Roma plum, small red cherry cluster, broad ribbed red beefsteak, dusky Cherokee Purple type. Row 3: upright romaine, rounded butterhead, burgundy-edged red leaf, lobed green oakleaf. Row 4: red-purple bulb onion, tan yellow bulb onion, white bulb onion, slender white/green bunching scallions. No text, logos, pumpkins, flowers or faces. All positions are fixed for programmatic cropping.

Validation: 54 unit tests pass, lint and Next.js build pass. Crop browser QA uses four isolated fixture spaces/collection entries to verify decoded pictures for peppers, lettuce, tomatoes and onions in both growing spaces and Vault, desktop/mobile layouts, no horizontal overflow and WCAG A/AA checks. Generated sprite was visually inspected before integration. Screenshots use QA records; no user plants/photos were overwritten.
